# templates/ — 共识观点库模板（公开仓）

本目录给 **own-your-view** 的「共识观点库 MVP」提供空模板与虚构示例。

## 公开仓放什么 / 不放什么

| 放 | 不放 |
|----|------|
| `views/consensus.empty.json`（空数组 `[]`） | 你的真实共识条目 |
| `views/consensus.example.json`（虚构示例，标明示例） | 含隐私或可识别信息的推敲记录 |
| 本 README | 个人绝对路径、bot 名、自动同步/邮箱通知配置 |

真实「共识观点 / 现行判断」只应存在于 **你本机或个人工作区**（或你环境约定的枢纽位置），**不进**公开 GitHub 默认树。

## 形态（S2′）

- **单一 JSON 数组文件**：默认相对路径 `views/consensus.json`。
- 数组内**只含**已确认入库的条目；每条含 F1 字段，并含 `updated_at`（ISO 8601）。
- 不是一条一个 markdown；不把聊天记录整段塞进库。

## 在你工作区怎么放

1. 在个人工作区根（或你约定的项目根）创建目录，默认名：`views/`。
2. 复制空模板：
   - `templates/views/consensus.empty.json` → 你的 `views/consensus.json`
   - 需要对照字段时，打开 `consensus.example.json`（虚构，勿当真实条目）。
3. 若希望多项目共用一个库：用 Skill 中的**可选覆盖**指向统一绝对路径（人人可见、可选、知情）。
4. 写入门槛由 Skill 约束：推敲收尾询问；你说「写入 / 确认入库」后再落盘；目录/文件若不存在，**确认入库时再创建**；**不会（也不应）自动偷偷写入**。

## 与 Skill 职责的关系（摘要）

- **写入职责**：推敲并在确认后落盘。
- **决策复查职责**：计划/决策且主题相关时读库，以「智者建议 / 既往共识」提出，**不代拍板**。
- 默认当前助手兼两职；可选覆盖映射见 Skill 正文。

细节以仓库内 `skills/own-your-view/SKILL.md` 为准。
