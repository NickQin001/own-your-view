# Own Your View · 想清楚，再相信

[English](README.md) · 作者：[NickQin001](https://github.com/NickQin001) · [MIT 许可证](LICENSE)

早期试用版 **v0.1.4** · 2026-11-17 · [版本说明与下载](https://github.com/NickQin001/own-your-view/releases/tag/v0.1.4)

读到或听到一个让你产生共鸣的观点后，检查依据、反例和适用边界，再决定保留、修改或暂不确定。

## 本版改进

- 普通推敲按 **本轮理解 → 关键检验 → 一个问题** 组织；有实质内容才显示栏目，不重复复述、不填空栏。
- 直接答疑、收尾、查库和保存完成各按请求呈现，不每轮套审查报告。用户明确指定格式时按要求调整。
- 默认观点库固定在工作区根目录，进入子目录不另建库。正常查看直接展示实际条目，实际路径或读取问题仍说明。
- 仅在明确确认后创建或写入，保存后实际读回核验，并检查既有条目保留。

结构简化不减少事实核验、反例、替代解释和不确定性要求。与 AI 达成一致不等于观点已被证明。

## 开始使用

支持 Skill 的宿主可按自身安装方式使用 [skills/own-your-view](https://github.com/NickQin001/own-your-view/tree/v0.1.4/skills/own-your-view)。版本页提供完整源码 ZIP 和 SkillHub 专用上传 ZIP。

能读取文件的助手，可以先解压源码包，再让它读取 `skills/own-your-view/SKILL.md`；也可以在聊天里提供完整文件。文件读取不等于原生 Skill 注册成功，纯文本聊天也未必具备持久文件读写能力。

> 请使用 own-your-view 帮我推敲：“工具越多，工作就越高效。”我的理由是，每个工具都能节省一点时间。先聚焦最影响判断的一处问题。

若宿主支持技能选择器，可调用 `$own-your-view`。已安装副本不会随仓库更新自动升级。

## 对话与共识观点库

普通推敲先回应本轮变化，检查关键问题，再按需追问。反例不适用时应撤回；可以保留分歧、阶段性收尾或承认暂时不知道，不强迫改口。你明确要求停止时，立即停止。

正常收尾后，可以明确确认保存现行判断。默认文件是工作区根目录下的 `views/consensus.json`。同一工作区切换子目录仍使用同一库，不同工作区各用自己的库；你明确指定其他位置时才调整。安装、读模板或查看库不会提前创建文件。

条目保留主张、适用边界、关键反例与回应、可推翻条件、日期及 `updated_at`。保存的是可复查的现行判断，不是绝对真理。公开仓库只有[空模板与虚构示例](templates/README.md)，不收录真实共识。

如果宿主个人规则强制每轮输出六段，需要由你明确增加适用例外；Skill 不会覆盖宿主指令，也不会自行修改全局设置或同步私人观点库。

## 验证范围与局限

v0.1.4 在一个新审查线程内生成了 9 个虚构对话场景响应，并完成 8 个隔离文件操作样例。已审阅输出与文件结果，覆盖缺失/损坏库、未确认不写、确认追加保留旧条目及首次建库后的读回。

这些是同线程批量场景，后续输入提前可见；文件动作按案例 ID 编排。结果只支持本次观察，不能证明通用意图识别、自动 Skill 选择、逐项独立会话、跨模型一致性或长期学习效果。详见[本轮验收摘要](tests/20261116_呈现与观点库验收.md)及[发行说明](RELEASE_NOTES.md)。

本 Skill 用于日常观点和阅读感悟的推敲，不替代专业建议。可用工具和聊天保存方式由宿主决定；Skill 不增加遥测或自动反馈提交，不将私人判断上传到本仓库。
