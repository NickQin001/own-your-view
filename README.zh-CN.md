# Own Your View · 想清楚，再相信

[English](README.md) · 作者：[NickQin001](https://github.com/NickQin001) · [MIT 许可证](LICENSE)

早期试用版 v0.1.1 · 2026-10-14 · [GitHub 项目](https://github.com/NickQin001/own-your-view)

听到一句很有道理的话之后，我们可能愿意相信它，甚至照着做。这个 Skill 希望在两者之间留一点空间：检查依据、看看反例，再决定哪些部分值得保留。

它不以说服你认同 AI 为目标，也不承诺把观点打磨成“绝对正确”。你可以反驳 AI、保留原观点、暂不确定，或随时结束。

## 为什么准备放到 GitHub

希望找到也有“共鸣之后想再检查一次”需求的人，通过实际使用的问题和建议一起改进。发布意图是邀请试用与讨论，不是宣称方法成熟或学习效果已经被证明。

本项目采用 MIT 许可证，允许使用、修改、再分发和商业使用，要求保留版权与许可声明。项目由 NickQin001 发起，使用 AI 辅助起草与检查。尚未完成安装验证或真实用户效果测试。

## 从哪里开始

- [核心指令](skills/own-your-view/SKILL.md)：唯一运行入口；无必需的其他 Skill、脚本或用户档案目录。
- [反馈说明](FEEDBACK.md)：怎样提供有用且不泄露隐私的反馈。
- [借鉴记录](SOURCES.md)：哪些机制来自已有项目，哪些设计另作选择。
- [测试方案](tests/测试方案.md)：规则检查和真实用户效果检验分别怎么做。
- [检查记录](tests/检查记录.md)：已完成、未完成与已知限制；不是效果认证。

在支持读取本地文件的 AI 环境中，明确让它读取并按核心指令开始，例如：

```text
请读取并使用 skills/own-your-view/SKILL.md。
我读到一个观点：“工具越多，工作就越高效。”这句话让我有共鸣。
我自己也觉得少做重复劳动会节省时间，但不确定这个结论的边界，请帮我推敲。
```

相对路径以本文件所在文件夹为基准。没有本地文件读取能力时，可手动提供核心指令和待推敲观点，但这不等于已完成 Skill 安装或跨平台兼容验证。安装步骤依赖所用工具；当前没有执行全局安装。

也可以只提供自己的概括，不必一开始就上传原文或全部资料。若结论取决于原话或具体事实，AI 才应指出需要补充哪一小段、为什么。

回复默认跟随你提问的语言，也可以明确要求另一种语言。中文提问中粘贴英文原文，不会仅因原文是英文就切换回复语言；混合语言参考主要表达与对话上下文。语言适配仍依赖所用模型，测试覆盖与限制见检查记录。

## 可以期待什么

AI 可以直接指出问题或举反例，通常一次聚焦一个关键问题。推荐改写默认等你回应后再给；你也可以直接说“先帮我改一版”。事实和来源需要查证，偏好可以保留；没有检索能力时应明确哪些还不知道。

适合验证的正常收尾会留下一项可选的小验证，或者一个需要查证的问题；仅请求整理、解释或表达偏好时，不额外添加作业。你不必完成作业才能结束。实践可能让你继续做、调整做法，也可能让你决定不做；这些都不是失败。

## 试用边界

首版面向主动检查日常观点和阅读感悟的使用情境，不是课堂考核、心理诊断或高风险专业决策工具。检索依赖宿主环境实际提供的能力；Skill 本身不增加联网权限。

有两种不同的检验：规则模拟检查只能观察 AI 的行为；自愿参与的换情境测试，才开始观察用户能否独立判断。两者都不足以单独证明长期认知提升。

本包无遥测、自动反馈提交或持久用户画像；这不等于宿主 AI 平台不保存聊天，私人内容仍需按所用平台的设置和政策处理。公开反馈前请自己检查脱敏范围。
